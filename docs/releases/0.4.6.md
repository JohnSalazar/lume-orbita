# Lume Orbita 0.4.6 — automatic updater APK cleanup

**Evaluation prerelease; publication explicitly approved after artifact review. Physical installation and cleanup validation on the KONKA remain pending.** Package `br.com.lume.launcher`, version **0.4.6/code 32**, Android TV/Google TV **11/API 30 or later**, target SDK **35**. The existing evaluation signing identity and MIT license are retained.

## Change

After a durably confirmed successful update, Lume removes orphaned APKs from its private updater-cache directory, including remnants of older failed attempts. A later foreground resume can retry cleanup for the recorded installed version if an earlier deletion failed. Maintenance is automatic and does not require a new setting.

Active downloads, prepared APKs waiting for confirmation and staging sources retain an ownership lease. Maintenance skips pending native sessions and removes only regular files with Lume's exact generated APK naming pattern, under the canonical private cache parent. It does not recurse, follow symbolic links, remove the installed app, clear user preferences, alter Home or delete other-app caches. Android continues to manage its native installer staging. The small bounded success journal remains available for recovery and retry.

Deletion errors do not change installation success into an error. Each pass is bounded; files that cannot yet be removed remain eligible for a subsequent retry. The existing 24-hour expiry on manual update checks uses the same active-file protection.

## Installation and platform limit

Use **Settings > About > Check for updates**, download and validate the APK, then confirm installation with Android using the remote. Preserve the same package/signature and a fresh private configuration backup. Physical verification must separately confirm installed identity, configuration/Home, orphan cleanup and the updated Android contracts.

The real 0.4.5 test confirmed that the KONKA blocks automatic foreground return and resumes the previous HBO task, even though Lume remains Home. This release does not bypass that restriction or promise automatic return; press Home after installation. No overlay, alarm workaround, root or protected-setting change is introduced. The false post-install error was not reported in the 0.4.5 physical test.

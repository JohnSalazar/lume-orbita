# Lume Orbita 0.4.3 — user and administrator guide

## Scope and requirements

Lume Orbita is an original Kotlin/Views launcher for Android TV and Google TV **11/API 30 or later**. This evaluation release is version **0.4.3**, `versionCode 29`, package `br.com.lume.launcher`, targeting SDK 35. Original code is licensed under MIT; third-party photographs, libraries and trademarks retain their own rights. No root or modified firmware is required.

The application supports 21 locales. Automatic follows the first compatible TV language and falls back to US English. A manual choice is retained locally; clocks follow the locale's default short time format. This changes Lume, not Android's global language, time zone or other applications' content. The [21 localized guides remain in the repository](https://github.com/JohnSalazar/lume-orbita/tree/v0.4.3/docs/i18n); this guide and the attached documentation bundle use technical US English.

## Install or update through ADB

1. Use the manufacturer's official developer/debugging settings and authorize your computer on the TV. Confirm the actual device serial with `adb devices`; do not assume another emulator or TV is the intended target.
2. Download the release APK and `SHA256SUMS.txt`. Verify the asset before installation. Expected APK SHA-256:

   ```text
   ada4b84a3b9d850ad6c5588c59900b14ead590a8e8f7d31937bae2813067b463
   ```

3. Record the current Home launcher, Lume version and relevant settings. Keep a current private backup and another working launcher available.
4. Install or update using the exact authorized serial:

   ```text
   adb -s DEVICE_SERIAL install -r lume-orbita-0.4.3.apk
   ```

5. Open Lume, inspect your configuration and press Home from another application. Test standby separately. An update is not an instruction to replace or reset the selected Home application.

Normal data-preserving updates require the same package and compatible signing identity. This release uses the existing evaluation certificate, with signer SHA-256:

```text
c435b38a840b6381b56c2f71f6e914f7958218762139b47ecd9607793cd67cdb
```

Keep signing material private. The in-app updater requires exact equality with the current signer-certificate set; a historical signing-lineage match alone is insufficient. Automatic key rotation is outside this update path. A custom build signed with another key is not a normal update to this APK. Do not uninstall or clear data to bypass a signature conflict; doing so can remove the configuration you want to retain. This certificate and device testing do not constitute Play Store or universal OEM certification.

## Use the manual updater

1. Open the top gear, then **About > Check for updates**. GitHub is contacted only after this action; there are no periodic or boot-time checks.
2. If no newer compatible release is found, keep the installed version. Connectivity, rate limits or changed metadata can cause a recoverable error. Use **Try again** when appropriate rather than repeatedly issuing requests.
3. If an update is offered, inspect its version and evaluation status, then choose **Download update**. This retrieves the expected release assets and displays progress. Back cancels the application's operation.
4. Lume validates downloaded bytes, checksum, package, actual version, minimum SDK and current signers. It rejects incompatible, unverifiable or non-newer APKs. Downloading alone does not start installation.
5. Once verification succeeds, choose **Install update**. This is a separate confirmation from downloading.
6. If Android requires source access, choose **Allow this source**. Decide personally in the official package-specific Android settings. Lume does not grant this permission itself or through ADB. Return to Lume to continue; opening Settings alone does not prove authorization or install anything.
7. Review Android's native PackageInstaller confirmation. You may refuse or cancel. OEMs can provide a different UI or omit a compatible path; every TV is not guaranteed to support it.
8. After a successful update, reopen Lume and verify its version, settings and Home behavior. If the OEM changes Home, **Review Home selection** opens official settings for a manual decision. Lume does not reset Home automatically.

At validation time, installed 0.4.3 queried public 0.4.2 and found no newer version. Once 0.4.3 is published, another 0.4.3 installation should still show no newer version until a legitimate higher release exists. Do not use an older or fictitious release to force this path.

## Storage, network and authorization boundaries

The fixed public source is `JohnSalazar/lume-orbita` on GitHub. Discovery considers at most 30 releases. Limits are 1 MiB of release JSON, 64 KiB of checksums, 32 MiB of APK data and three approved HTTPS redirects. A checksum from the same repository detects corruption but is not an independent authenticity root. Local signer comparison remains mandatory.

An APK is staged temporarily in private internal storage and the Android session also needs space. This is separate from online screensaver photographs, which remain in application RAM. The updater does not require Downloads access or broad storage permission and cleans up only its owned temporary files and confirmed sessions.

Network requests have a 60-second transport deadline; the UI also has a 60-second watchdog per check or download/validation operation. These do not include the user's permission and installation dialogs. Slow DNS can keep the single bounded worker occupied after logical cancellation. Do not repeatedly retry to create more work or bypass rate limits.

The updater does not use GitHub credentials, cookies or application telemetry and does not upload preferences, favorites, history or streaming accounts. GitHub/CDN servers naturally receive the IP address and ordinary request. Detailed device evidence and backups should remain private.

## Recovery and rollback

- If discovery, verification or installation fails or is canceled, keep the existing installation. Do not clear preferences, uninstall, grant source access through shell commands or modify firmware to make a retry succeed.
- Keep another working launcher available. If Home changes after replacement, select the appropriate launcher in Android's official settings and verify the Home button before removing anything.
- An old APK does not guarantee a data-preserving downgrade, especially for a non-debuggable release. Recovery may require a forward-versioned corrective build with the same signing identity. Do not assume `-d` bypasses Android restrictions.
- Attempts are correlated by owner, session and token so stale callbacks cannot act on a later attempt. A process stop between session creation and recording its ID can leave an owned orphan and conservatively block new attempts until cleanup or expiration. Do not abandon unidentified sessions or delete unrelated files.
- Before uninstalling Lume, select and verify another working Home application. Uninstallation removes application data; it is not an update or a configuration-preserving rollback.

## What was tested

The delivery passed 172 JVM tests, the core coverage gate (441/442 lines; 817/859 branches), eight Android contract cases and 294 updater-state panels across 21 locales. All 483 new compiled strings matched the catalogs. Lint reported 0 errors and 18 warnings. Physical testing preserved 16 typed preferences, Home and source access, which remained false.

Those 294 panels cover 14 **updater states**, not the whole launcher. Some states were rendered as controlled fixtures. No future-release PackageInstaller installation, source-permission grant or complete native update was performed. No fictitious release was published to manufacture that result. Core coverage does not represent the whole Android installation stack; logical watchdog tests do not establish a measured 60-second platform timeout. This update did not repeat native-language review, FPS, standby, HDMI or third-party playback tests and does not guarantee every OEM configuration.

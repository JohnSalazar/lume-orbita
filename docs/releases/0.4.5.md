# Lume Orbita 0.4.5 — recovery after self-update

**Evaluation prerelease; publication explicitly approved after artifact review. Physical installation and automatic return on the KONKA remain pending.** Package `br.com.lume.launcher`, version **0.4.5**, code **31**, Android TV/Google TV **11/API 30 or later**, target SDK **35**. The existing evaluation signing identity and MIT license are retained.

## Corrections

- Recover a successful self-update when Android terminates the outgoing process and blocks the installer-result Activity.
- Persist the validated target code, APK SHA-256, signer set and correlated attempt before committing new updates. Verify the installed package before recovering success; an absent session alone is not success.
- Receive Android's protected package-replacement event privately and request a one-time return to Lume only if it was and remains the selected Home. A blocked return does not become an installation failure.
- Reconcile before restaging or showing an error after Activity recreation. Retain the explicit native installation confirmation flow and existing translated messages.
- Handle a fresh update initiated by 0.4.4 through a narrower protected-event migration path with recorded ownership, version increase, own install source and unchanged Lume Home. That older version did not persist exact target pins; its migration must not be described as the new full-identity verification path.
- Reject stale/duplicate completion and results from another active attempt. Preserve the existing warning for any changed default Home, without selecting a launcher automatically.

No dependency, installation permission, user-preference migration, firmware change or UI redesign was added. The implementation does not open HBO or another streaming application; Android can temporarily expose a previous task during package replacement.

## Upgrade and limits

Use **Settings > About > Check for updates**, download and validate the candidate, then select **Install update** and confirm Android's dialog with the remote. Keep the same package/signature; do not uninstall or clear Lume to update. Preserve a fresh private backup and compare settings/Home after the real test.

Android/OEM policy still controls automatic foreground opening. If the system refuses the return request, press Home; the verified result must remain available without a false installation error. No promise is made that every frame of the previous system task can be suppressed. No root, overlay, alarm workaround, silent confirmation or automatic Home-setting change is introduced.

# Lume Orbita 0.4.3 — manual GitHub updates

**Evaluation prerelease** for Android TV and Google TV **11 or later**. Package: `br.com.lume.launcher`; `versionCode`: **29**; minimum SDK: **30**; target SDK: **35**. Original code is distributed under the [MIT License](https://github.com/JohnSalazar/lume-orbita/blob/v0.4.3/LICENSE). This release retains the existing evaluation signing certificate and the application's 21 locales.

## Changes since 0.4.2

- **About > Check for updates** checks the project's public GitHub releases only after a user click. No periodic checks, boot-time checks or silent installations were added.
- **Download update** retrieves a candidate from the fixed repository. Lume validates payload limits, SHA-256, the actual package/version/minimum SDK and exact equality with the current signer-certificate set. Checking does not start downloading, and downloading does not start installation.
- **Install update** is a separate action after verification. Android's PackageInstaller requires confirmation. If source access is required, the user decides in Android settings; Lume does not grant it automatically.
- Android's normal same-package, compatible-signature update mechanism preserves application data. The updater does not uninstall the package, clear preferences or force Home. If the OEM changes Home, **Review Home selection** opens the official settings for a manual decision.
- All 23 updater strings are translated into the 21 supported locales. Existing launcher navigation, visual design, locale-aware clocks and screensaver behavior remain in place.
- Attempt ownership, session/token correlation and bounded background work prevent delayed callbacks from acting on a later attempt and prevent unbounded request queues.

## Installation and update

For a compatible existing installation, verify the checksum and use authorized ADB with the exact device serial:

```text
adb -s DEVICE_SERIAL install -r lume-orbita-0.4.3.apk
```

Do not uninstall Lume or clear data to force an update. A different signing certificate cannot replace the existing installation through a normal update. Check Home after installation; OEM behavior varies. Keep another working launcher and use Android's official selector if recovery is needed.

The existing evaluation certificate supports the tested update path; this is not Play Store certification or a universal device-compatibility guarantee. See the [user and administrator guide](https://github.com/JohnSalazar/lume-orbita/blob/v0.4.3/docs/releases/0.4.3-guide.md).

## Validation actually performed

- **172 JVM tests passed**, including 14 transport/download contracts and four installation-attempt identity regressions.
- Core coverage: **441/442 lines and 817/859 branches**. This is core coverage, not coverage of the entire Activity, network stack or native installer.
- Release and instrumentation builds completed. Lint reported **0 errors and 18 warnings**.
- **Eight Android contract cases** exercised selection/metadata boundaries and rejection of the installed APK when falsely advertised as a future version.
- **294 updater-state panels** were rendered: 21 locales × 14 updater states, with **483 compiled new strings** matching their catalogs. These are updater panels, not a repeat of the earlier whole-launcher matrix. No geometry issues were recorded in the 1,050 measured text instances; Back closed the panel in all 21 locales.
- The physical KONKA/API 30 run preserved all **16 typed preferences**, Home and existing access. Source authorization remained **false**. No permission was granted through ADB.
- The real GitHub query used installed **0.4.3** against the then-public **0.4.2**, correctly returning no newer version. After this release is published, an installation already on 0.4.3 should likewise find no newer version until a legitimate higher release appears.

Installation states were rendered for UI verification, but **no future-release PackageInstaller installation or source-permission grant was completed**. No fictitious APK or release was published to force that test. Controlled fixtures and logical watchdog activation are not evidence of an end-to-end native update or a measured 60-second wait.

## Limits and remaining risks

Discovery is limited to 30 releases. Bounds are 1 MiB of JSON, 64 KiB of checksums, 32 MiB of APK data and three approved HTTPS redirects. Transport requests and UI operations have separate 60-second deadlines; time spent authorizing a source or confirming installation is separate. Delayed DNS can still occupy the single bounded worker after logical cancellation.

A process interruption between Android session creation and persistence of its ID can leave an owned orphan. Further attempts fail conservatively until cleanup or expiration rather than abandoning an unidentified session. APK/session storage is temporary and private; online screensaver photographs retain their separate RAM-only application behavior.

GitHub/CDN availability, rate limits and OEM installation/Home behavior remain external constraints. A checksum hosted with the APK does not replace verification of the installed signing identity. No root, firmware modification, silent-install permission or automatic Home reset was used. Native-language review and fresh FPS, standby, HDMI and third-party playback tests were not performed for this update.
